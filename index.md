# Introduction

The way in which *cybersecurity* is growing as a central aspect of all ICT projects is certainly unprecedented. As for everything else, AI dramatically accelerated this growth, with worries about the ability of companies to keep up with this trend. With Claude Mythos, the tipping point may have been reached where we need to heavily rethink the development of ICT systems. This, in my opinion, is a revolution in the sector similar to nothing we have seen before.

What I am envisioning for the future is a world where ICT projects are developed and built with one primary objective: **security**. In other words, we are approaching a world where, *security by design* will become the norm, rather than the exception.

It is not only AI that is urging us to switch to a security-centred approach, our society and our economy is vitally dependent on the digital infrastructure. We cannot pay, work, exercises, warmup, cook without the digital infrastructure fully functioning. 

The geopolitical situation doesn't help either, the word war has come to fashion again (and, unfortunately, not just the word) and it now includes *cyberwar*. The digital systems of a country are now reachable targets for any enemy (and not only) country. Sadly, civilians infrastructure, vital for the population (supplies, hospitals, ...) are not left out of war, leaving exposed and vulnerable every single citizen of a country that is engaging with another one.

Where does this all leave us? The only question that I can give is *focus on security*. We have to start designing security built-in in all projects and at all stages of the implementation. Security is not a feature anymore, is not a plus anymore, it is now a requirement that cannot be ignored and that must be the centerpiece of the whole system.

This book aims at supplying some basic principles of security with ideas as how to implement them and how to proceed with *security by design* as the leading principle. The tool proposed in this book is a framework I called **SD-3D**: *Security-Drive Design, Development, and Deployment* by which we advocate security as driver of all the stages in a system lifetime. During *design* security must be built into the project, during *development* security must drive the advances (much like Test Driven Development, from which I'm taking inspiration), and during *deployment* security must be guaranteed and verified. In other words the SD-3D framework prescribes action to make security driven advances as much as possible preventing the creation of vulnerabilities that need then to be fixed.

The remaining of this book is divided into four parts. Part I covers the basic of security and will develop the necessary concept and terminology used in the rest of the book. Part II will focus on Security-Driven Design, describing how security can be included in the design stage. Part III will move to Security-Driven Development where we will extend the Test Driven Development (TDD) principles to security. Finally, Part IV covers Security-Driven Deployment focusing on the techniques that can be used to enact, monitor, and improve the security of the system in operation.

This book is intended for all ICT professionals. The three D's can be seen as mainly directed to software engineers (design), developers (development), and system administrator (deployment). However, security is a holistic concept and no one can be fruitfully working towards security without knowing how security enters a project in its entirety. Thus, I recommend reading this book entirely without skipping any part. While the Part I "Principle of Security" is a prerequisites for the remaining parts, each part from II to IV is mostly independent from the other (although cross references are present).
